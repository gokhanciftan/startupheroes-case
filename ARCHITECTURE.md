# Architecture Question

## Objective

The goal is to design a simple data pipeline that stores both historical operational data and processed order delivery statistics in a centralized data warehouse.

The solution should answer the following questions:

- How is historical data transferred from the operational database?
- How is processed data transferred from Kafka?
- Which technologies are used?
- Why were these technologies selected?
- How does the data flow through the system?

---

## Technology Selection

### PostgreSQL

PostgreSQL is used as the operational database where application data is stored. It acts as the source of historical order information.

### Apache Kafka

Apache Kafka stores the processed `order_delivery_statistics` events produced by the application. It provides a reliable and scalable event streaming platform.

### Apache NiFi

Apache NiFi is responsible for transferring data from both PostgreSQL and Kafka into the data warehouse.

It was selected because it provides:

- Visual data flow management
- Centralized pipeline administration
- Built-in monitoring
- Retry mechanisms
- Back-pressure handling
- Provenance tracking
- Easy maintenance through a graphical interface

Using Apache NiFi allows both ingestion pipelines to be managed from a single platform.

### Google BigQuery

Google BigQuery is selected as the centralized data warehouse.

It stores both historical operational data and processed analytical data while providing high-performance analytical querying capabilities.

## Data Flow

The proposed data flow consists of two independent ingestion pipelines.

### Historical Data Pipeline

1. Historical order data is extracted from PostgreSQL.
2. Apache NiFi transfers the data into the **RAW** layer of BigQuery.
3. The original operational data is preserved for future analysis and reprocessing.

### Processed Data Pipeline

1. Processed `order_delivery_statistics` events are published to Apache Kafka.
2. Apache NiFi consumes these events.
3. The processed data is loaded into the **ANALYTICS** layer of BigQuery.

---

## BigQuery Structure

To separate raw operational data from processed analytical data, the warehouse is organized into two logical layers.

```
BigQuery

raw
└── orders_history

analytics
└── order_delivery_statistics
```

### RAW Layer

The RAW layer stores historical operational data exactly as it exists in the source database.

This allows future reprocessing if business rules change.

### ANALYTICS Layer

The ANALYTICS layer stores processed business metrics generated by the application.

These datasets are optimized for reporting, dashboards, and analytical queries.

---

## Reasons

This architecture was designed to keep operational workloads separated from analytical workloads.

Using Apache NiFi provides centralized management of both ingestion pipelines, while Google BigQuery offers a scalable and fully managed data warehouse for storing historical and processed data.

Separating the warehouse into RAW and ANALYTICS layers improves maintainability, preserves original data, and enables future analytical processing without impacting the operational database.
